# Full Model 表现问题排查文档

## 1. 文档目的

当前项目已经完成了输入特征流程整改，并确认：

- 模型已进入 raw mode
- 文本原始特征与图像原始特征已被实际读取
- `text_proj` 与 `img_proj` 已经在模型内部定义为可训练投影层
- 投影层参数已经进入优化器并参与训练

这意味着，先前“随机投影缓存冻结”这一核心方法学问题已经基本被排除。  
如果接下来 `full model` 的表现仍然不理想，或者仍旧无法稳定优于 baseline，那么更应重点排查以下四类原因：

1. residual 分支过强
2. 融合设计本身存在问题
3. 数据集上的视觉模态收益有限
4. 训练策略或优化路径存在问题

本文档将针对这四类原因做详细分析，并形成待办清单，供后续逐项验证。

## 2. 当前前提

在进入本轮排查前，需要明确以下前提已经成立：

- 缓存流程已经不再是当前最主要的问题
- 模型已经不再依赖缓存阶段的固定随机投影结果
- 当前的 full model 已经具备公平使用原始文本/图像特征并学习任务投影的能力

因此，后续排查应聚焦于模型结构、数据条件和训练动态，而不是继续把责任归结为旧缓存方案。

## 3. 可能性一：Residual 分支过强

### 3.1 问题机制

当前 full model 同时包含：

- 融合分支
- residual 分支

而 residual 分支的本质是为每个实体学习一个可训练补偿向量，再叠加到融合表示上。  
这意味着 residual 分支具有较强的“实体记忆”能力，尤其在封闭实体集的链接预测任务中，它可能天然比多模态融合更容易降低训练损失。

### 3.2 为什么现在更值得怀疑

在输入特征流程修正之后，如果 full model 仍旧不能稳定优于 `residual-only`，那说明问题不再主要来自模态特征输入，而更可能来自 residual 分支本身“过于容易学”。

具体可能表现为：

- 模型训练时优先依赖 residual 分支
- 融合分支虽然存在，但实际贡献较小
- residual 分支成为一条优化捷径

### 3.3 典型现象

如果 residual 过强，可能会出现以下情况：

- `residual-only` 长期表现非常高
- `full model` 与 `residual-only` 的差距很小，甚至更差
- 调整模态相关模块时，结果变化不明显
- 调整 residual 强度时，结果变化明显

### 3.4 如何验证

建议重点做以下实验：

- 比较 `residual-only` 与 `full model`
- 增大 residual 正则，看 full model 是否受益
- 降低 residual 分支容量，看 full model 是否受益
- 记录 residual scale 的训练曲线
- 记录 normalized mix 中 residual 权重的变化

### 3.5 预期判断标准

如果在限制 residual 后，full model 的表现反而提升，或者多模态分支的贡献明显上升，那么可以较强地判断当前问题确实来自 residual 过强。

## 4. 可能性二：融合设计本身存在问题

### 4.1 问题机制

当前 full model 的融合方式是：

- 先将文本和图像投影到统一维度
- 再经过 `t_adapter` / `v_adapter`
- 用关系感知门控机制进行逐维融合

这种设计理论上合理，但并不意味着一定适合当前数据和任务。  
可能的问题包括：

- 逐维 gate 太细，带来不稳定优化
- relation-aware bias 没有真正学出有意义的差异
- 模态间对齐方式仍不够自然
- 更简单的融合方式反而更稳

### 4.2 为什么现在更值得怀疑

在 raw mode 已经建立的前提下，如果多模态分支仍然不能稳定发挥作用，就不能再简单地把问题归为“输入坏了”。  
这时就必须认真怀疑：当前 relation-aware gate 是否真的是当前任务最合适的融合设计。

### 4.3 典型现象

如果融合设计本身有问题，可能会出现：

- `early fusion` 或更简单融合方式不比当前 gate 差
- gate 分布没有明显关系差异
- 有图实体与缺图实体上的 gate 差异不明显
- 改 gate 相关超参数时表现波动大但没有稳定提升

### 4.4 如何验证

建议增加以下对照：

- 当前 relation-aware gate
- 不带 relation-aware bias 的普通 gate
- scalar gate
- concat + MLP
- early fusion

### 4.5 预期判断标准

如果更简单的融合方式稳定优于当前 relation-aware gate，那么问题更可能来自当前融合结构本身，而不是 residual 或数据条件。

## 5. 可能性三：数据集上的视觉模态收益有限

### 5.1 问题机制

多模态模型能否显著优于结构或文本模型，并不只取决于模型本身，也取决于数据集是否真正提供了有价值的视觉信息。

在 OpenBG-IMG 这类数据上，可能存在以下现实情况：

- 图像并不总和关系语义高度相关
- 一些关系本身几乎不需要视觉信息
- 一些图像质量较差，甚至带来噪声
- 有图实体虽然有图片，但图片对链接预测没有实质帮助

### 5.2 为什么现在更值得怀疑

当模型已经具备：

- raw feature
- 可训练投影
- 合理的模态融合路径

如果多模态收益仍不明显，就必须考虑数据本身的视觉上限问题，而不能无限度继续修改模型。

### 5.3 典型现象

如果视觉模态收益有限，常见现象包括：

- full model 只在少数关系类型上有提升
- 有图实体提升有限，甚至不稳定
- 缺图实体基本主要靠结构/文本
- 图像加入后平均结果不升反降

### 5.4 如何验证

应重点做分组分析：

- 有图实体 vs 缺图实体
- 不同关系类型
- 典型成功样本 vs 失败样本
- 图像可用但无收益样本占比

### 5.5 预期判断标准

如果视觉收益只集中在少数局部场景，那么后续论文方向就应更加偏向“多模态收益边界分析”，而不是“提出一个普遍更强的新方法”。

## 6. 可能性四：训练策略或优化路径存在问题

### 6.1 问题机制

即使模型结构本身没有明显问题，如果训练策略不合适，也可能导致 full model 没有学好。

潜在问题包括：

- 多模态分支和 residual 分支学习节奏不平衡
- 学习率、batch size、warmup 设置不合适
- gate regularization 目标值不合理
- image dropout 比例不合适
- 训练时过早停在了对多模态不利的局部最优

### 6.2 为什么现在更值得怀疑

你已经开始调整 `batch_size` 和 `early_stop_patience`，这说明训练超参数本身已经可能对结果造成影响。  
在 raw mode 下，训练路径相较旧版已经改变，所以之前的超参数未必仍然合适。

### 6.3 典型现象

如果训练策略是主因，可能会出现：

- 不同 seed 波动大
- 结果对 patience、batch size、dropout 很敏感
- full model 有时明显有效，有时明显无效
- gate 分布在训练中早早塌缩

### 6.4 如何验证

建议优先做低成本的训练策略对照：

- 调整 early stop patience
- 调整 batch size
- 调整 image dropout
- 调整 gate regularization
- 调整 fusion warmup
- 观察多 seed 稳定性

### 6.5 预期判断标准

如果在不改模型结构的前提下，仅通过训练策略就能显著提升 full model 稳定性，那么问题更偏训练优化，而不是结构设计。

## 7. 推荐排查顺序

为了避免同时改太多因素，建议按以下顺序排查：

1. 先查 residual 是否过强
2. 再查训练策略是否不合理
3. 再查融合结构本身是否有问题
4. 最后判断数据集上的视觉收益边界

这个顺序的理由是：

- residual 过强和训练策略问题往往成本最低、最容易先验证
- 融合结构改动成本更高，应放在后面
- 数据收益边界分析需要建立在前面结果相对稳定的基础上

## 8. 阶段性目标

通过上述排查，最终需要回答以下问题：

1. full model 目前不稳定或不够强，主要是 residual 压制、融合设计、训练策略，还是数据本身限制？
2. 是否存在一种简单可行的改法，使 full model 稳定优于 baseline？
3. 如果不能稳定优于 baseline，论文是否应转向分析驱动型而非方法改进型？

## 10. 当前建议

当前最理性的做法不是继续无限制改模型，而是先按照本文档逐项排查。

如果在 raw mode 下，full model 经过 residual 控制和训练策略修正后仍然不能稳定优于 baseline，那么就应认真考虑把论文主线调整为：

- 多模态收益边界分析

而不是继续强行坚持“方法改进型”叙事。
