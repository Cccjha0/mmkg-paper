# Residual-Only 强于 Full Model 的排查清单

## 1. 文档目的

这份文档用于系统排查当前项目中 `residual-only` 表现强于 `full model` 的原因，并将后续工作整理为可执行的实验待办清单。

本文档不预设结论，不默认将问题归因于“融合方式错误”，而是从模型定义、输入特征、训练动态和评测协议四个层面逐步排查。

## 2. 当前现象

从现有结果看，`residual-only` 在当前实验中表现明显强于 `full model`。这意味着当前必须认真回答以下问题：

- `full model` 是否真的有效利用了多模态信息
- `residual-only` 是否本质上是一个更强的结构化 baseline
- 多模态分支是否因为输入质量或训练路径问题而没有发挥作用
- 当前结果是否受到评测协议或实验设置的影响

## 3. 优先级最高的原因假设

### 假设 A：`residual-only` 本质上是一个很强的实体参数模型

#### 解释

在当前实现里，关闭 fusion 后，模型仍保留按实体索引学习的残差向量。这意味着 `residual-only` 并不是“只保留一部分多模态能力”，而更接近：

- 每个实体一个可训练向量
- 再配合 `ComplEx` 解码器做链接预测

在封闭实体集链接预测任务中，这类模型可能天然很强。

#### 为什么这很重要

如果这个假设成立，那么当前结果不能简单解释为“融合比残差差”，而应解释为：

- 当前 `residual-only` 是一个强结构化 baseline
- 当前多模态模块尚未提供足够增益去超过这个 baseline

#### 待办事项

- [ ] 明确在论文和实验记录中重新定义 `residual-only` 的口径，避免把它写成轻量多模态 baseline
- [ ] 增加一个真正的 `text-only` 结构模型对照
- [ ] 增加一个“不含实体独立残差”的融合对照
- [ ] 比较 `residual-only` 与 `text-only`、`gate-only` 的性能差距

#### 预期判据

如果 `residual-only` 远强于 `text-only`，且接近或超过所有 multimodal 变体，那么说明实体参数化能力本身是主要来源。

### 假设 B：多模态输入特征质量不足，导致 fusion 分支先天吃亏

#### 解释

当前缓存流程中，文本和图像原始特征先经过随机初始化线性投影，然后保存为固定 embedding。训练阶段不再更新投影层。

这可能导致：

- 原始语义信息被随机压缩
- 输入模态特征与下游任务不对齐
- fusion 模块只能在低质量固定特征上做组合

#### 为什么这很重要

如果 fusion 接收的是不稳定特征，而 residual 直接学习实体参数，那么训练时模型自然更倾向使用 residual。

#### 待办事项

- [ ] 重构文本缓存流程，改为保存原始文本特征
- [ ] 重构图像缓存流程，改为保存原始图像特征
- [ ] 在模型内部加入可训练投影层
- [ ] 重跑 `gate-only`、`full model`、`early fusion`
- [ ] 对比修正前后多模态模型的收益变化

#### 预期判据

如果改为可训练投影后，`gate-only` 和 `full model` 明显提升，说明当前问题主要不在 fusion 结构，而在输入特征流程。

### 假设 C：residual 分支太强，吞掉了 fusion 分支的学习空间

#### 解释

当前 `full model` 同时包含：

- fusion 分支
- entity residual 分支

如果 residual 更容易快速降低训练损失，模型就可能优先依赖 residual，而不是学习如何使用文本和图像。

这会出现一种典型情况：

- 训练看起来正常
- full model 也收敛
- 但 fusion 实际贡献很弱

#### 为什么这很重要

这类问题不是“融合形式完全错误”，而是“优化路径存在捷径”。

#### 待办事项

- [ ] 记录训练过程中 fusion 分支和 residual 分支的混合权重变化
- [ ] 记录 residual scale 的训练曲线
- [ ] 增加更强的 residual 正则化实验
- [ ] 尝试减小 residual 分支容量
- [ ] 尝试 fusion warmup 或 residual warmup
- [ ] 观察不同训练阶段 gate 分布是否有明显变化

#### 预期判据

如果限制 residual 后，full model 的多模态收益开始上升，则说明当前主要问题是分支竞争，而不是单纯 fusion 结构失效。

### 假设 D：当前 fusion 方式没有真正匹配任务需求

#### 解释

当前融合方式是基于关系感知的逐维门控。这个设计本身合理，但仍可能存在以下问题：

- gate 粒度过细或过粗
- relation-aware bias 学得不足
- 文本和图像进入 gate 前的适配不充分
- 当前任务更需要关系特定的模态选择，而不是统一逐维混合

#### 为什么这很重要

如果前面几类问题排查后依然无效，才有理由认真怀疑 fusion 机制本身。

#### 待办事项

- [ ] 比较当前 relation-aware gate 与普通 gate
- [ ] 比较当前 gate 与简单 concat + MLP
- [ ] 比较当前 gate 与 scalar gate
- [ ] 观察不同关系下 gate 分布是否确实有区分度
- [ ] 分析 gate 对有图实体和缺图实体是否呈现不同模式

#### 预期判据

如果更简单的融合方式稳定优于当前 relation-aware gate，才可以较强地判断当前 fusion 设计存在结构性问题。

## 4. 不能忽视的次级原因

### 假设 E：当前评测协议放大了某类模型的优势

#### 解释

当前训练主要在 `dev` 集上 early stop，并以当前评测流程选择最佳 checkpoint。若评测协议偏窄，可能会放大某类模型的优势。

尤其需要注意：

- 当前评测是否只关注 tail prediction
- 当前最优结果是否只是 dev 最优，而不是 test 泛化最优
- 不同模型是否在过拟合程度上存在差异

#### 待办事项

- [ ] 建立明确的 `train/dev/test` 流程
- [ ] 在固定协议下重新选取最佳 checkpoint
- [ ] 补充 test 集汇报
- [ ] 比较 dev 最优和 test 最优的一致性

#### 预期判据

如果 `residual-only` 在 dev 上远强，但到 test 上优势明显缩小，说明当前结论部分来自模型选择过程。

### 假设 F：图像模态本身对当前数据集贡献有限

#### 解释

OpenBG-IMG 虽然包含图像，但不代表图像一定对所有关系都有强贡献。可能出现的真实情况是：

- 一部分关系几乎不需要图像
- 一部分实体图像噪声大
- 一部分图像与知识图谱关系对齐较弱

#### 待办事项

- [ ] 按关系类型统计多模态收益
- [ ] 分析有图实体中哪些类别受益明显
- [ ] 抽取典型成功案例与失败案例
- [ ] 比较图像可用但无收益的样本比例

#### 预期判据

如果图像收益只集中在少数关系或少数实体子群，说明问题不一定是模型错，而可能是数据本身的上限有限。

## 5. 建议的实验执行顺序

### 第一阶段：先确认是不是 baseline 定义问题

- [ ] 重新梳理 `residual-only` 的机制定义
- [ ] 明确它是否属于结构模型而非真正多模态模型
- [ ] 补齐 `text-only` 和其他公平 baseline

### 第二阶段：优先修输入特征流程

- [ ] 缓存原始文本特征
- [ ] 缓存原始图像特征
- [ ] 将投影层移入模型训练
- [ ] 重跑关键对照实验

### 第三阶段：检查是否存在分支竞争

- [ ] 记录 residual scale
- [ ] 记录 normalized mix 权重
- [ ] 增加 residual 正则与容量控制实验
- [ ] 观察 full model 对这些改动是否敏感

### 第四阶段：最后才验证融合方式本身

- [ ] scalar gate
- [ ] 普通 gate
- [ ] concat + MLP
- [ ] 当前 relation-aware gate

## 6. 每轮实验都应统一记录的内容

为了避免后面再次无法解释结果，后续每轮实验建议统一记录：

- [ ] seed
- [ ] best dev MRR
- [ ] test MRR
- [ ] hits@1 / hits@3 / hits@10
- [ ] 是否使用可训练投影
- [ ] residual scale 最终值
- [ ] fusion/residual 混合权重
- [ ] gate 均值与方差
- [ ] 有图实体与缺图实体分组结果

## 7. 最终要回答的问题

这份排查清单最终不是为了证明某个模块“有问题”，而是为了回答以下问题：

1. `residual-only` 强，是因为它本来就是强结构 baseline，还是因为 full model 设计不合理？
2. 当前多模态分支弱，是因为输入特征质量不足，还是因为优化路径被 residual 抢占？
3. 如果在修正输入和训练后 full model 仍然不强，是否说明 fusion 结构本身需要改？
4. 如果 full model 只在特定场景下优于 residual-only，论文是否应转为“多模态收益边界分析”而不是“提出一个全面更强的新模型”？

## 8. 执行原则

后续排查必须遵守以下原则：

- 不预设“融合一定是对的”
- 不预设“融合一定是错的”
- 不把一次实验结果直接上升为方法结论
- 每个假设都要有对应实验和明确判据

只有按这个方式推进，后续实验结果才能真正转化为论文可用证据。
