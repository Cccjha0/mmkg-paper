# C05/C06: column identity and base-model reconstruction

Read-only audit of the existing 18 checkpoints, both datasets and all three architectures. No training, hyperparameter selection, TEST selection, full candidate scoring or historical result replacement. Numerical tests use only six-entity synthetic models. Reuse the completed 72-cell raw-score and endpoint audits for actual frozen-model numerical coverage; their limitations remain in force.

## Identity and direction contract

OpenKE input (head, tail, base relation) becomes canonical (head, base relation, tail). Preserve the bijection to contiguous IDs. Publish entity and relation names in ID order as UTF-8 JSON arrays. The canonical mapping digest hashes the name-to-ID object with sorted keys, ensure_ascii=False and compact separators. The ordered digest applies the same serialization to the ID-ordered name array (no newline); the file digest separately hashes its indented bytes including the final newline.

Production `validate_pair` requires identical mappings, split order, counts, seed, dataset and protocol. `score_expert_block` enumerates arange(N), creates canonical candidate triples, and concatenates contiguous chunks: column j means entity ID j for both scorers. Tail substitutes t; head substitutes h. M-Hyper alone uses reciprocal head scoring (t, r+R, candidate h), with checkpoint buffer [R,...,2R-1,0,...,R-1]. NativE and AdaMF retain r and score (candidate h,r,t). All return higher-is-better values: M-Hyper query/entity dot product, NativE/AdaMF margin minus RotatE distance. The ensemble never negates just one model.

Reject a different or partial entity universe instead of taking an intersection, padding missing entities, or silently permuting score columns. Check all checkpoint entity/mask rows and model relation rows. Missing modalities retain the structural candidate with zero feature rows and explicit masks. This is different from non-finite scores. Finite-score normalization cannot repair ID mismatch. Existing abnormal-score handling is disclosed separately in Appendix A; the actual 72-cell audit has zero exceptional rows. No claim is made of support for a new partially covering scorer.

## Training record and provenance boundary

Publish all 18 full merged configurations, checkpoint/config digests, first strictly maximal DEV epoch and final epoch, plus six dataset-by-architecture settings. Link every original record to its prior bound diagnostic and training manifest. Source commit f2e8198d24d5dde56476fc768a56436adf72e2ba is an audited, retrievable reconstruction snapshot. Check all tracked training-package Python files against that tree, allowing only CRLF/LF conversion, and publish both hashes. It is not evidence that this revision executed the historical training. Old bare state_dict files do not contain an execution revision, epoch, optimizer state, runtime environment or RNG state. Preserve these unknowns explicitly.

Distinguish (1) released-script/README numerical settings, (2) local protocol adaptations, (3) DEV checkpoint choice. No base hyperparameter search ledger has been established; do not call these six configurations DEV-tuned optima. M-Hyper generic embedding.d, neg_ratio and adv_temperature are inactive. AdaMF mu=0 disables its adversarial contribution to the base-model gradient even though generator updates still run. The released dataset scripts also use mu=0; do not call this full MAT training or substitute the README's different LR.

`rebuild_paper_a_base_model.py` prints a plan by default. An explicit --train is CUDA-only, checks the source inventory and canonical manifest, launches the original trainer with the complete recorded configuration and a separate output root, and writes an execution receipt. It does not select on TEST or overwrite old checkpoints. This supports rebuilding from the exact supplied frozen features, not recovery of unknown image/text encoders, exact historical training binaries or bitwise checkpoint reproduction.
