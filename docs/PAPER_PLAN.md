# 多模态知识图谱补全论文计划修订稿

## 1. 当前项目的真实基础

本项目已经完成的核心工作不是前后端展示，而是一个围绕 OpenBG-IMG 的多模态知识图谱补全实验框架，主要包括：

- 文本缓存与图像缓存构建流程
- 基于 `ComplEx` 的链接预测训练框架
- 关系感知门控融合
- 实体级残差补偿
- 缺失图像占位向量与图像模态 dropout
- `early fusion`、`gate-only`、`residual-only`、`fusion+residual` 等配置分支

因此，论文工作不应再表述为“提出一个从零开始构建的新模型”，而应表述为：

- 对现有多模态知识图谱补全框架进行问题收敛、机制修正与实验重构
- 在缺失视觉模态和模态信息不稳定条件下，分析并改进模型的鲁棒性

## 2. 先做理性判断

当前版本具备论文雏形，但还不适合直接进入投稿写作阶段。主要原因不是“工作太少”，而是“证据链还不完整”。

目前最重要的现实判断如下：

1. 当前方法具备一定研究价值，但创新类型更接近“问题导向的结构改进”，而不是“通用型基础模型创新”。
2. 当前代码已经能支撑论文原型，但实验结论与论文叙事之间仍存在脱节。
3. 如果不先修正评测协议、输入特征流程和 baseline 定义，后续写出来的论文说服力会明显不足。

因此，论文规划必须从“描述一个看起来合理的方法”转向“建立一个经得起质疑的论证过程”。

## 3. 当前草案需要修正的核心问题

### 3.1 论文主线不能默认设定为“多模态融合显著优于其他方法”

从现有结果看，项目里的 `residual-only` 配置表现非常强。这意味着当前最需要回答的问题不是“如何进一步吹强多模态模型”，而是：

- 为什么结构补偿项会表现得如此强
- 当前多模态融合是否真的带来了稳定增益
- 多模态模块在哪些实体或关系类型上有效
- 多模态模块在哪些场景下反而没有贡献

如果这个问题不先解释清楚，论文很容易出现叙事与结果不一致的问题。

### 3.2 当前 `residual-only` 的含义需要谨慎界定

在当前实现中，关闭 fusion 后，模型会退化为实体级可训练残差表示加解码器。它并不等价于“只保留多模态补偿，不做融合”，而更接近一种强结构化实体嵌入模型。

因此，后续论文里不能模糊地把它当作“轻量多模态 baseline”，而应明确说明：

- 它本质上是一个强实体参数化 baseline
- 它主要反映结构学习和实体私有表示的能力
- 它与真正的 multimodal baseline 在机制上并不完全同类

### 3.3 输入特征处理流程存在明显方法学风险

当前缓存流程中，文本和图像原始特征会先经过随机初始化线性投影，再保存为固定向量。训练阶段并不会继续优化该投影层。

这个设计的问题在于：

- 增加了不可解释的随机信息损失
- 让多模态特征质量受一次性随机投影影响
- 审稿时容易被追问为什么不在训练中共同优化投影层

这不是一个“可优化的小细节”，而是应优先修正的核心方法问题。

### 3.4 当前评测协议还不够论文化

现有训练流程主要在 `dev` 集上做 early stopping 和模型选择，当前评测实现也以 tail prediction 为主。

如果直接基于这一套结果写论文，会有几个明显问题：

- `dev` 与 `test` 的职责边界不够清晰
- 结果可能更接近“调参最优 dev 成绩”，而不是最终泛化表现
- 评测维度仍偏窄，难以支持完整主结果表

因此，论文计划中必须单列“评测协议整改”，而不能把它附属于普通实验任务。

## 4. 建议的论文定位

### 4.1 更稳妥的定位

当前工作更适合定位为以下三类之一：

- 面向缺失视觉模态的多模态知识图谱补全方法
- 面向模态不稳定场景的关系感知融合与结构补偿方法
- 一篇以实验分析为主、兼具结构改进的 MMKG 方法论文

### 4.2 不建议的定位

当前阶段不建议将论文定位为：

- 全新通用 MMKG 基础框架
- 显著超越现有主流模型的统一方法
- 单纯强调“多模态融合一定优于结构模型”的结论型论文

原因很简单：以当前证据看，这些表述都偏强，风险高于收益。

## 5. 建议重新定义研究问题

相比原草案，更建议将研究问题收敛为下面两种之一。

### 方案 A：方法改进型

研究问题可以定义为：

“在多模态知识图谱补全任务中，当视觉模态存在缺失或噪声、且其与结构语义对齐不稳定时，如何设计关系感知融合与实体补偿机制，以提高链接预测的鲁棒性和性能？”

这个版本适合在后续严格实验中，full model 能稳定优于合理 baseline 时采用。

### 方案 B：分析驱动型

研究问题可以定义为：

“在缺失视觉模态条件下，多模态信息在知识图谱补全中何时有效、何时失效？关系感知融合与实体补偿机制对这一问题能否提供稳定改进？”

这个版本更稳健。即使最终 full model 不是绝对最强，也依然可以支撑论文。

从当前仓库状态看，优先推荐方案 B，因为它更符合现有证据结构，也更不容易在结果上自相矛盾。

## 6. 建议保留的论文贡献点

论文贡献不宜写多，最多保留 2 到 3 个，而且每一点都必须能被实验独立验证。

建议贡献点如下：

1. 提出一个面向缺失视觉模态场景的关系感知融合与实体补偿框架。
2. 设计针对缺图实体和模态不稳定场景的训练机制，包括缺失占位向量、图像 dropout 及可控融合配置。
3. 通过系统实验分析多模态信息与结构补偿在不同实体组别、关系类型和缺模态条件下的作用边界。

其中第三点很重要。它不是“补充分析”，而是这篇论文能否成立的关键。

## 7. 优先级应重新排序

原草案把大量精力放在“补结果”和“写论文”上，但更理性的顺序应该是下面这样。

### P0：必须先完成的方法与评测整改

- 将随机固定投影改为模型内可训练投影，缓存原始文本和图像特征
- 明确 `residual-only`、`gate-only`、`early fusion` 的机制定义和论文口径
- 建立清晰的 `train/dev/test` 使用流程
- 明确最终论文主模型，不再继续扩散试验分支

如果这一层不完成，后续所有实验都可能需要重跑。

### P1：重新建立可信的主结果矩阵

- 在统一协议下重跑 `text-only`
- 重跑 `early fusion`
- 重跑 `gate-only`
- 重跑 `residual-only`
- 重跑 `full model`
- 至少 3 个随机种子
- 报告平均值和标准差

### P2：形成论文真正有价值的分析结果

- 有图实体与缺图实体分组结果
- 不同关系类型下的表现差异
- gate 分布与 residual 强度分析
- 成功案例与失败案例

### P3：决定最终论文方向

- 如果 full model 稳定优于其他合理 baseline，则采用“方法改进型”主线
- 如果 full model 仅在特定场景占优，则采用“分析驱动型”主线
- 如果 residual-only 长期最强，则必须诚实调整论文叙事，避免夸大多模态贡献

## 8. 后续实验应回答的关键问题

后续实验不是为了“把表格填满”，而是为了回答以下问题。

### 8.1 多模态信息是否真的带来稳定收益

需要回答：

- full model 是否稳定优于 early fusion
- full model 是否稳定优于 gate-only
- full model 是否稳定优于 text-only
- full model 相对 residual-only 的优势到底是否存在

### 8.2 多模态收益出现在哪些子群体

需要回答：

- 缺图实体上，多模态机制是否仍有效
- 有图实体上，图像模态是否带来可观提升
- 哪些关系更依赖视觉信息
- 哪些关系主要依赖文本或结构

### 8.3 门控与残差是否真的学到了可解释模式

需要回答：

- gate 值是否会随关系变化
- 缺图实体与有图实体的 gate 分布是否不同
- residual 强度是否在困难实体上更高
- image dropout 是否真的提升了对缺模态或噪声模态的鲁棒性

## 9. 建议的论文结构

### 9.1 如果采用方法改进型主线

可采用如下结构：

1. 引言
2. 相关工作
3. 问题定义与方法
4. 实验设置
5. 主结果与消融
6. 分组分析与可视化
7. 结论

### 9.2 如果采用分析驱动型主线

更建议采用如下结构：

1. 引言
2. 相关工作
3. 任务背景与问题设定
4. 模型框架与实验设置
5. 主结果对比
6. 多模态收益边界分析
7. 案例研究与误差分析
8. 结论

如果后续结果不能强力支撑“新方法明显最好”，第二种结构会更稳。

## 10. 现实可达的投稿目标

从当前项目基础出发，更现实的目标应该是：

- 第一目标：形成一篇结构完整、评测规范、实验充分的论文稿件
- 第二目标：在结果稳定后，尝试投稿偏应用或方法改进型期刊

关于分区，不建议在现阶段过早承诺。比“能投几区”更关键的是：

- 是否有清晰的问题定义
- 是否有规范的实验协议
- 是否有经得起追问的 baseline
- 是否有和结论一致的结果解释

如果这些问题处理得好，论文自然有基础；如果这些问题处理不好，单纯追求更高分区意义不大。

## 11. 建议的执行路线

建议后续按以下顺序推进。

### 第一阶段：修正方法与协议

- 重构缓存与输入特征流程
- 整理模型分支
- 定义论文主模型和 baseline
- 建立规范评测流程

### 第二阶段：重跑关键实验

- 统一配置
- 统一 seed
- 统一结果记录格式
- 输出可直接用于论文的主表

### 第三阶段：做分析而不是只报数字

- gate 可视化
- residual 分析
- 分组实验
- 错误案例

### 第四阶段：根据证据决定论文叙事

- 证据支持方法改进，就写方法论文
- 证据更支持边界分析，就写分析论文

## 12. 最终原则

这份论文计划的核心原则应当是：

- 不预设结论
- 不夸大创新
- 不回避与预期不一致的实验结果
- 让研究问题、代码实现、实验协议和论文叙事保持一致

只有在这个前提下，当前项目才有可能从“可展示的毕设系统”真正转化为“可投稿的论文工作”。
