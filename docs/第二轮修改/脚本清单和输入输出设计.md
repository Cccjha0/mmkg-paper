下面我把它直接拆成一套**可落到 repo 的脚本体系 + 文件契约 + 字段设计**。

先说明一下约束：这套设计会严格沿用你论文主稿里已经写死的口径，包括：

- official model-comparison line 和 routing-compatible line 必须分开
- router 训练只用 dev-side labels / priors
- test 只用于最终评估
- gain margin 扫描是 `δ ∈ {0.00, 0.01, 0.02}`
- threshold scan 是 `τ ∈ {0.1, 0.3, 0.5, 0.7, 0.9}`
- router feature 集合要与论文 Table 3 / Table 10 保持一致
   这些都已经在当前 manuscript 里明确了

# 4. 每个脚本的职责 + 输入输出字段设计

## 4.1 `scripts/export_query_level_outcomes.py`

这是最底层、最关键的导出脚本。

### 作用

把某个模型在某个 split 上的 **query-level outcome** 导出来，不导 candidate 全表，只保留后面 router / analysis 真正要用的字段。

### 典型输入

```
python scripts/export_query_level_outcomes.py \
  --run-dir ml/artifacts/outputs/openbg_img_gate_only/20260327_185713_seed3 \
  --split test \
  --model-name gate_only \
  --evaluation-line routing_compatible \
  --out outputs/router/raw/test_gate_only_query_outcomes.parquet
```

### 输入参数

- `--run-dir`
- `--split {dev,test}`
- `--model-name`
  - `gate_only`
  - `residual_only`
  - `full_model`
  - 可扩展
- `--evaluation-line`
  - `routing_compatible`
  - `official`
- `--out`
- `--topk 2`
   用来算 `margin = top1_score - top2_score`

### 输出文件

```
outputs/router/raw/{split}_{model_name}_query_outcomes.parquet
```

### 输出字段

| 字段               | 类型   | 说明                                         |
| ------------------ | ------ | -------------------------------------------- |
| `query_id`         | string | 唯一 query 标识                              |
| `split`            | string | `dev` / `test`                               |
| `model_name`       | string | `gate_only` / `residual_only` / `full_model` |
| `evaluation_line`  | string | `routing_compatible` / `official`            |
| `source_run_dir`   | string | 来源 run                                     |
| `source_seed`      | int    | 来源 seed                                    |
| `direction`        | string | `head` / `tail`                              |
| `head_id`          | string | 原 triple 的 head                            |
| `relation_id`      | string | relation                                     |
| `tail_id`          | string | 原 triple 的 tail                            |
| `target_entity_id` | string | 当前 query 的 gold target                    |
| `target_has_img`   | int    | 0 / 1                                        |
| `target_regime`    | string | `head_has_img / head_no_img / tail_no_img`   |
| `rank`             | int    | filtered rank                                |
| `rr`               | float  | reciprocal rank                              |
| `correct_score`    | float  | gold entity score                            |
| `top1_score`       | float  | top-1 candidate score                        |
| `top2_score`       | float  | top-2 candidate score                        |
| `margin`           | float  | `top1_score - top2_score`                    |
| `is_correct_at_1`  | int    | rank==1                                      |
| `is_correct_at_10` | int    | rank<=10                                     |

### 备注

这个脚本要同时支持：

- `Gate-only`
- `Residual-only`
- `Full Model`

其中：

- `Gate-only` / `Residual-only` 主要用于 routing-compatible line
- `Full Model` 主要用于 official line 下的 RQ1 补充分析

## 4.2 `scripts/build_relation_priors.py`

### 作用

只用 dev split 的 expert outcome，构造 relation-level priors。
 这一步必须 dev-only，因为你主稿已经把这个纪律写进去了 

### 典型输入

```
python scripts/build_relation_priors.py \
  --gate-dev outputs/router/raw/dev_gate_only_query_outcomes.parquet \
  --residual-dev outputs/router/raw/dev_residual_only_query_outcomes.parquet \
  --out outputs/router/raw/dev_relation_priors.csv
```

### 输入文件

- `dev_gate_only_query_outcomes.parquet`
- `dev_residual_only_query_outcomes.parquet`

### 输出文件

```
outputs/router/raw/dev_relation_priors.csv
```

### 输出字段

| 字段              | 类型   | 说明                          |
| ----------------- | ------ | ----------------------------- |
| `relation_id`     | string | relation                      |
| `support`         | int    | dev query 数                  |
| `fusion_mean_rr`  | float  | gate-only 平均 RR             |
| `struct_mean_rr`  | float  | residual-only 平均 RR         |
| `mean_rr_gain`    | float  | `mean(rr_gate - rr_residual)` |
| `fusion_win_rate` | float  | `P(rr_gate > rr_residual)`    |
| `struct_win_rate` | float  | `P(rr_residual > rr_gate)`    |
| `tie_rate`        | float  | tie 比例                      |
| `is_visual_prior` | int    | 二值标记，可按规则生成        |

### 推荐规则

`is_visual_prior = 1` 当且仅当：

- `support >= min_support`
- `fusion_win_rate > 0.5` 或 `mean_rr_gain > 0`

`min_support` 推荐默认 20，和你 relation-group supporting analysis 的 minimum-support 口径一致会更顺。

## 4.3 `scripts/build_router_feature_table.py`

这个脚本负责把 query outcome + relation prior + modality metadata 拼成 router dataset。

### 作用

输出两个层次：

- `router_features_dev.parquet`
   训练 router 用
- `router_features_test.parquet`
   推理用
- 可选额外输出 `router_eval_targets_test.parquet`
   后处理分析用

### 典型输入

```
python scripts/build_router_feature_table.py \
  --gate-dev outputs/router/raw/dev_gate_only_query_outcomes.parquet \
  --residual-dev outputs/router/raw/dev_residual_only_query_outcomes.parquet \
  --gate-test outputs/router/raw/test_gate_only_query_outcomes.parquet \
  --residual-test outputs/router/raw/test_residual_only_query_outcomes.parquet \
  --relation-priors outputs/router/raw/dev_relation_priors.csv \
  --out-dir outputs/router/features
```

### 训练表输出

```
outputs/router/features/router_features_dev.parquet
```

### 推理表输出

```
outputs/router/features/router_features_test.parquet
```

### 评估目标输出

```
outputs/router/features/router_eval_targets_test.parquet
```

- `gain_label_*`

| `gain_label_d001` | int    | post-hoc only   |
| `gain_label_d002` | int    | post-hoc only   |
| `target_regime`   | string | convenience     |

### 输出字段

| 字段                  | 类型   |
| --------------------- | ------ |
| `regime`              | string |
| `n_queries`           | int    |
| `mrr_oracle`          | float  |
| `mrr_xgb_routed`      | float  |
| `oracle_gap`          | float  |
| `false_negative_rate` | float  |
| `false_positive_rate` | float  |
| `lost_rr_mass_fn`     | float  |
| `lost_rr_mass_fp`     | float  |

### `lost_rr_mass` 定义建议

- `lost_rr_mass_fn`
   对 oracle 应该选 gate 但 router 没选的 query，累加 `rr_gate - rr_residual`
- `lost_rr_mass_fp`
   对 oracle 应该选 residual 但 router 误选 gate 的 query，累加 `rr_residual - rr_gate`

这样能把 “gap 到底输在哪” 说清楚。
