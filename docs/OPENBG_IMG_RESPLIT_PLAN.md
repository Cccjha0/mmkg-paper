# OpenBG-IMG 论文评测重划分方案

## 1. 当前数据口径现状

当前 OpenBG-IMG 原始文件的实际情况如下：

- `OpenBG-IMG_train.tsv`：`230087` 条，三列 `(h, r, t)`
- `OpenBG-IMG_dev.tsv`：`5000` 条，三列 `(h, r, t)`
- `OpenBG-IMG_test.tsv`：`14474` 条，两列 `(h, r)`

也就是说，当前 `test.tsv` 是**查询集**，不是带真值尾实体的标注测试集，因此：

- 它可以用于最终提交预测
- 但**不能**用于论文里的 `MRR / Hits@1 / Hits@3 / Hits@10` 标准汇报

此外，当前 `dev.tsv` 中的实体和关系都已经被 `train.tsv` 覆盖：

- `dev` 中未见于 `train` 的实体数：`0`
- `dev` 中未见于 `train` 的关系数：`0`

这说明当前数据本身适合做一个**封闭实体集链接预测**的标准重划分。

## 2. 为什么必须重划分

如果论文要做正式汇报，就必须满足：

- `train / dev / test` 都是三列标注三元组
- `dev` 只用于 early stopping 和 model selection
- `test` 只用于最终汇报
- 各模型在同一固定划分上比较

当前官方文件里没有带标注的 `test.tsv`，所以若不重划分：

- 你只能汇报 `dev` 结果
- 这不符合标准论文评测协议
- 后续 `mean ± std`、主结果表、分组实验都会缺少正式 `test` 基础

## 3. 重划分总体原则

建议从**所有带标注三元组**中重建论文专用划分。

可用带标注池为：

- `OpenBG-IMG_train.tsv`
- `OpenBG-IMG_dev.tsv`

合并后总量：

- `235087` 条三元组

重划分必须满足四个约束：

1. `train` 中必须保留所有关系至少一条  
原因：否则某些关系在训练中根本不可学。

2. `train` 中必须保留所有出现在 `dev/test` 中的实体  
原因：当前任务是封闭实体集链接预测，不应该让 `dev/test` 出现训练中从未出现的实体。

3. `dev/test` 应尽量保持关系分布稳定  
原因：避免某些高频关系只集中在一个集合里，导致结果波动或偏差。

4. 划分随机性必须固定  
原因：论文必须可复现。

## 4. 推荐的论文专用划分方案

### 4.1 推荐方案

我建议使用：

- `train = 220087`
- `dev = 5000`
- `test = 10000`

总计仍为：

- `235087`

这个方案比例如下：

- `train`：约 `93.62%`
- `dev`：约 `2.13%`
- `test`：约 `4.25%`

### 4.2 为什么这样分

原因有三点：

1. 你当前历史实验已经长期使用 `5000` 条 `dev`

保持 `dev=5000`，后续迁移成本最低，也便于与你已经观察到的历史趋势衔接。

2. `test=10000` 已足够稳定

对当前数据规模来说，`10000` 条测试三元组足够形成稳定的 `MRR / Hits` 汇报，而且比 `5000` 更适合作为主结果表依据。

3. `train` 仍然足够大

即使拿出 `15000` 条做 `dev+test`，训练集仍有 `22` 万级别三元组，不会因为划分而明显削弱训练规模。

## 5. 推荐的具体划分策略

不要直接纯随机切分。  
建议使用**关系分层 + 训练覆盖保护**的两阶段策略。

### 5.1 第一步：构造候选池

先把：

- 原 `train.tsv`
- 原 `dev.tsv`

合并成一个统一的标注池，例如：

- `all_labeled.tsv`

### 5.2 第二步：按关系分桶

按 `relation` 把所有三元组分桶。

对每个关系桶，按固定随机种子打乱，例如：

- `split_seed = 20260326`

### 5.3 第三步：先抽 dev/test 候选

按关系比例，从每个关系桶中抽样：

- 一部分进入 `dev`
- 一部分进入 `test`

推荐比例不是机械按总比例，而是：

- 先保证每个关系在 `dev/test` 中尽量都有样本
- 再用余量按全局比例补齐到 `5000 / 10000`

### 5.4 第四步：做训练覆盖修正

这是最关键的一步。

抽出 `dev/test` 之后，必须检查：

- 某个实体是否只剩在 `dev/test`，不再出现在 `train`
- 某个关系是否被完全抽空出 `train`

如果出现这种情况，就把相关三元组从 `dev/test` 放回 `train`，并从同关系桶里补抽其它候选。

### 5.5 第五步：最终一致性校验

最终必须确认：

- `train/dev/test` 互不重叠
- 三者并集等于全部标注池
- `dev/test` 中所有实体都出现在 `train`
- `dev/test` 中所有关系都出现在 `train`
- 三个文件都保持三列 TSV 格式

## 6. 推荐输出文件

建议不要直接覆盖原始文件，而是在新目录下保存论文专用划分。

推荐目录：

- `data/datasets/openbg_img/paper_split/`

推荐文件名：

- `OpenBG-IMG_paper_train.tsv`
- `OpenBG-IMG_paper_dev.tsv`
- `OpenBG-IMG_paper_test.tsv`
- `split_meta.json`

其中 `split_meta.json` 建议记录：

- 划分时间
- 划分脚本版本
- 随机种子
- 三个集合大小
- 实体覆盖检查结果
- 关系覆盖检查结果

## 7. 和原始 query-only test 的关系

原始：

- `data/datasets/openbg_img/raw/OpenBG-IMG_test.tsv`

不要删除，也不要拿来做论文主指标。

它的更合理定位是：

- 保留为“官方查询集”
- 用于最终演示、推理导出、案例展示
- 不参与论文主结果表

论文正式评测使用你新建的：

- `OpenBG-IMG_paper_test.tsv`

## 8. 论文中应如何表述

建议写法：

> OpenBG-IMG 原始公开文件中仅提供查询式测试集，而未提供带标注答案的标准测试三元组。为开展标准化链接预测评测，本文将原始标注三元组集合重新划分为 train/dev/test，并固定随机种子与覆盖约束，以保证所有 dev/test 实体与关系均在训练集中出现。

这个表述是合理的，前提是你：

- 明确说明为什么要重划分
- 提供划分规则
- 保证可复现

## 9. 推荐执行步骤

### 9.1 脚本实现

新增一个划分脚本，例如：

- `ml/training/scripts/build_openbg_img_paper_split.py`

功能应包括：

- 读取原 `train.tsv + dev.tsv`
- 按关系分层抽样
- 做实体/关系覆盖修正
- 写出新的 `paper_train/dev/test`
- 输出 `split_meta.json`

### 9.2 划分后校验

脚本跑完后，自动输出：

- 各集合三元组数
- 各集合关系数
- `dev/test` 中未被 `train` 覆盖的实体数
- `dev/test` 中未被 `train` 覆盖的关系数
- 关系分布偏差摘要

### 9.3 配置切换

在正式论文实验配置中，把数据路径切到：

- `paper_split/OpenBG-IMG_paper_train.tsv`
- `paper_split/OpenBG-IMG_paper_dev.tsv`
- `paper_split/OpenBG-IMG_paper_test.tsv`

### 9.4 实验纪律

一旦正式划分确定，就不要再频繁重切。  
后续所有主模型、所有 seeds、所有分组实验都必须共用这一套固定划分。

## 10. 我建议你现在就采用的结论

最稳妥的方案是：

- 不再尝试把当前 query-only `OpenBG-IMG_test.tsv` 强行当作论文测试集
- 用 `train + dev` 合并得到的 `235087` 条标注三元组，重建一套论文专用三列 `train/dev/test`
- 固定为 `220087 / 5000 / 10000`
- 保证 `dev/test` 中所有实体和关系都被 `train` 覆盖

这套方案最符合你当前论文目标，也最容易在后续写作中自圆其说。
